# Objective

Improve the application's UI/UX by replacing all native JavaScript confirmation dialogs \(e.g., window.confirm/alert used for destructive or consequential actions\) with the project's existing shadcn/ui Dialog component, so confirmations are consistent with the app's design system.

Simplify the sidebar by removing the 'Local data · Online enhancement' card entirely.

Restructure the card layouts on the Library and History pages: each card should span full width of its container, and all card actions currently exposed as visible buttons should be consolidated into a context menu triggered by a three-dots \(kebab/more-vertical\) icon positioned in the upper-right corner of the card.

## Requirements

- Replace every instance of native JavaScript confirmation \(window.confirm, window.alert, or similar\) that gates an action with a shadcn Dialog component; the dialog must present the same message/options \(e.g., confirm/cancel\) as the original native dialog.
- Ensure the replacement dialog blocks the action until the user explicitly confirms or cancels; canceling must abort the action exactly as before.
- Remove the 'Local data · Online enhancement' card from the sidebar without altering any other sidebar items, layout, or navigation behavior.
- On both the Library page and the History page, change each card to occupy the full available width of its parent container/grid cell.
- Move all action buttons currently rendered directly on Library and History cards into a dropdown/context menu opened via a three-dots icon button placed in the top-right corner of each card.
- Preserve every existing action and its behavior inside the new context menu; no functionality may be added, removed, or changed — only its presentation and placement.
- Use the project's established component conventions \(shadcn/ui DropdownMenu or equivalent for the context menu\) and keep styling consistent with the current design system.
- Keep code maintainable: prefer reusable components where the same confirmation-dialog pattern or card-with-context-menu pattern repeats across pages.

## Verification

- Confirm that every previously native-confirmed flow now opens the shadcn Dialog instead, and that confirming executes the action while canceling does nothing.
- Verify no remaining references to window.confirm/window.alert exist in the affected flows.
- Confirm the 'Local data · Online enhancement' card no longer appears in the sidebar and that all other sidebar elements render unchanged.
- Visually verify Library and History cards render at full container width across common viewport sizes, with no overflow or layout regressions.
- Verify the three-dots icon appears in the upper-right corner of every Library and History card and opens a context menu containing all original actions.
- Exercise each action from the new context menu to confirm it behaves identically to the previous inline buttons \(including any confirmation dialogs they trigger\).
- Run the existing test suite / build to confirm no regressions were introduced by these UI changes.
